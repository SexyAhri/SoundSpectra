# 音乐卡片设计与验收

## 三种布局

- `record` 唱片：独立封套、沟槽、盘缘与固定光泽层；18 秒匀速旋转，暂停只改变 animation-play-state，轮询及切歌不替换盘片 DOM。音乐只驱动九段小电平。
- `compact` 简约：小方封面、两行信息、细进度线，实际外轮廓高度最多 96 CSS px；四段单色声能提示，不再复用唱片轮廓。
- `afternoon` 午后 · 紧凑：奶油纸色、左侧唱片标签分栏、宋体主标题、低饱和七段线条；正文颜色固定为深绿，自动色仅作用于点缀。没有虚构的“午后电台”来源。

小尺寸先隐藏来源、状态和时间等次要信息，标题最低 15 CSS px，省略超长文本并提供 title 原文，不默认跑马灯。预览按真实屏幕逻辑尺寸排版后整体缩放，与原生卡片使用同一组件。大小、预设位置、精确坐标、恢复位置、拖动与方向键控件均保留。

## 曲目、封面与时间

`card-presentation.ts` 对曲目标识与封面地址同时核对，图片解码完成前显示明确的唱片占位。旧曲目解码迟到、无封面或错误图片不会挂到当前标题下；不堆退出层。切歌只对文字和封套做 280ms 小位移淡入，减少动态效果时不启动交接及旋转。

Windows 媒体快照在读取缩略图后重新核对标题、歌手、专辑及 track number；音源 revision 不匹配的请求不发布。移除只按标题、歌手和专辑复用旧缩略图的逻辑，允许同名歌曲和迟到封面刷新。当前媒体标识还包含音源、进程、时长及会话。前端原有串行轮询和 disposed 保护继续使用，不新增并行请求。

`card-clock.ts` 复用歌词的 `playbackPosition`。Windows LastUpdatedTime 按 1601 年起始的 100ns 时间转换，先校正媒体位置，前端以该次观测时间推进，不对 seek 缓动追赶。无可信时间轴、无时长、错误快照、未来异常时间或超过四秒的观测不显示进度。暂停冻结，恢复不重建 CSS 动画。

播放器报告的 playing 与真实音频声能各自独立。找不到媒体会话时不再把 audio listening 伪装成 playing；“声能安静”也不反向推断暂停。

## 配色与兼容

新增可选 `desktopCard.accentColor`，仅接受六位十六进制颜色。缺失或无效值回退继承场景，旧配置不新增默认固定色；Rust 保存时省略 None。卡片色按钮与颜色输入不再写全局 `color`，也不改歌词或其他区域。

继承封面配色复用 `useCoverColors` 与既有封面取色 Promise 缓存。卡片使用当前封面的目标色，而不是灯效仍在渐变的上一首颜色；新曲目缺封面立即使用场景固定色。灯效原有颜色渐变保留。场景导入导出携带局部色；不支持的局部色回退继承，其他无效方案字段仍校验拒绝。

声能沿用现有 96 格数据，只取前 72 格分组，未新增分析器、DSP、网络素材或 WebGL。平滑使用短起音、自然释放；静音归零后不写 SVG。隐藏预览停止视觉更新，桌面嵌入窗口不把 document.hidden 当成桌面不可见；离屏及关闭组件停动画。静音仍保留 180ms 的轻量输入检查，以便真实音频恢复。

## 证据与验证（2026-11-07）

本地审阅入口：`artifacts/card-review/review.html`。

- `comparison.png`：三款各为 480×152 逻辑布局框，左旧右新；相同原创封面与媒体夹具，两侧加载同一应用基础 CSS。
- `continuous-comparison.webm`：左右同步对照，依次展示三种样式的模拟切歌、暂停与恢复，无声音；不代表操作了 QQ 音乐。
- `readability.png`：304×100，小尺寸、长中文/英文/组合字符，缺封面/歌手/来源/时长，浅深背景。另有 240×80、320×100、480×152、720×220 布局边界与预览比例测试。
- `native/{record,compact,afternoon}-live.png`：真正 1420 开发版 WebView，QQ 的《不知所措》/ 王靖雯，保留用户当时 15% 宽度；不是 dist 或旧安装版。
- `native/continuous.html` 与 `native/frames.json`：开发版桌面层连续合成帧，未主动切歌、暂停或改音量，不作为物理呈现 FPS。
- `native/report.json`：4.03 秒整个桌面 WebView 的脚本时间 253.5ms、任务时间 960.2ms、布局时间 16.0ms；包含场景及歌词，不能归因于卡片，也不是卡片 FPS。采样期间未录屏。
- `native/idle.json`：现场播放器后来报告暂停，1.8 秒只读观测，电平、进度、卡片属性写入均为 0，进度及旋转角度不变；没有主动控制播放器。

定向验证包括：WinRT 时钟/seek/非法时间戳、封面格式、播放器匹配、快速同名切歌与迟到封面、错误封面、过期状态、暂停恢复的同一旋转动画对象、颜色隔离/区域编辑/旧方案兼容、所有位置参数、隐藏预览与嵌入桌面语义、静音无 DOM 写入及响应布局。只运行相关 Playwright 用例、Rust 过滤测试、类型检查和必要构建，未重复整套。构建仍有既有大 chunk 与 DSP 未使用项警告。

原生验收中发现启动阻塞：前端可能在 SceneMenu 注册前请求托盘收藏，原先 state() 导致进程 panic。`system_tray.rs` 改为 try_state() 返回可处理的未就绪错误，实机重启后正常。此为解除验收阻塞的最小防护，不改托盘功能。

临时只改卡片 variant、accentColor；每次读取最新完整配置再合并自己的字段，恢复时仅恢复仍等于本次临时值的字段。报告确认恢复唱片样式、无独立色、原大小与位置，其他设置未覆盖，桌面附着正常。没有改 QQ 播放、音量或曲目；未提交/推送。

## 限制

- GSMTC 不提供所有播放器一致的歌曲唯一 ID。若播放器本身在同一快照中错误配对新标题和旧封面，或连续两首的来源/所有元数据/时长/track number 全部相同，本实现不能凭空识别；跨请求竞态和本地旧缓存已防护。
- Windows 实机已验证，macOS 媒体适配器未实机验证；可选新字段允许旧适配器回退。
- 没有做多显示器/DPI/长时间 GPU 或所有播放器穷举，不把小范围采样称为完整性能结论。
