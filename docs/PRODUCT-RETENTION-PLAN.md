# SoundSpectra：可玩性与持续使用方案

日期：2026-11-06。状态：用户已批准第一、二阶段，第三阶段暂缓。下文保留产品判断与验证目标；实现范围见本节。

## 第一、二阶段的实现

- 「场景收藏 → 精选搭配」提供暖砂日常、暮蓝听歌、清浅专注。点选先预览，应用后可撤销；「另存为」收藏正在预览的方案，「保存当前」保存当前桌面。
- 完整收藏包含灯效、区域、遮罩、歌词展示、音乐卡片和封面跟色开关；旧灯效收藏保持兼容。最近使用记录会恢复上次选择，托盘「桌面方案」提供三套精选及最多三个最近收藏。
- 原生端以当前配置合并、验证并一次保存方案。总桌面开关、性能设置、歌词目录与同步偏移、音源和应用偏好保持独立。拾光绳的外观、位置、项目、顺序和挂载关系全部保持独立，本次不纳入方案。
- 预览区增加「跟随封面配色」和「固定当前配色」。每张封面只作小尺寸取色，最多缓存六张；灯效和音乐卡片柔和过渡。暂停时颜色收敛，缺图、纯色、灰阶或读取失败时回退固定颜色；遵守减少动态效果偏好，切歌不写入配置。
- 第三阶段的完整搭配分享文件、分享图片和在线作品库均未实现。现有导入导出继续只交换灯效、布局和遮罩，界面明确提示这一范围。

本地自动化验证覆盖方案隔离、保存失败与重试、撤销、重载、旧格式、浅深主题与短窄窗口，以及封面异步竞态、缓存和回退。实际留存、长时间常驻性能、真实多屏与休眠恢复仍需使用反馈，不能由自动化测试推断。

## 判断与定位

建议把核心体验收敛为：**打开喜欢的音乐，就拥有一张好看、顺手、属于自己的桌面。**

目标用户先选经常在电脑前听音乐、愿意美化桌面的人。不要同时为重度生产力用户、音乐播放器用户、壁纸创作者分别造一套系统。

可玩性来自「换一种搭配，马上看到变化」；持续使用来自「这套搭配值得保留，而且常用东西顺手可达」。拾光绳提供日常用途，音乐和个性化提供情绪价值，稳定性让两者能够长期常驻。

当前最值得解决的阻力是：调出满意桌面需要理解许多设置；几个模块的成果难以作为一个整体保存；交互故障会让用户不再信任桌面接管。继续增加零散控件，会放大这些阻力。

这是一组待验证的判断，不是已经证明会提高留存的结论。

## 现有能力与真正缺口

| 已有能力（依据当前代码） | 应继续补齐的部分 |
| --- | --- |
| 多区域音乐灯效、布局与遮罩 | 让普通用户先得到一套完整成品，再按需调整 |
| 场景收藏、导入导出 | 当前 `SceneLayout` 主要保存灯效区域和遮罩；扩展为包含歌词、音乐卡片等展示配置的桌面方案 |
| 壁纸取色、自动搭配 | 复用分析能力，减少首次配置步骤；不要再造另一个“智能搭配”入口 |
| 歌词、音乐卡片、歌曲识别 | 把可靠的歌曲状态和柔和的视觉联动连起来；无歌词、无封面时体面退化 |
| 拾光绳的程序、文件、照片、便签 | 保持固定顺序、可靠挂载恢复和快速打开，让用户每天有实际用途 |
| 浅色/深色主题、性能档位 | 所有新方案都检查两种主题、低性能档位和减少动态效果偏好 |

代码入口：`src/features/preview/scene-library.ts`、`scene-suggestions.ts`、`wallpaper-palette.ts`，以及 `src/features/spectrum/model.ts`、`src/features/rail/`。这里区分了已有功能与建议扩展，避免把“再做收藏/再做导入导出”当作新工作。

## 使用过程

首次使用：预览三套成品 → 套用一套 → 播放音乐看到响应 → 挂上几个常用项目或自己的照片 → 保存自己的方案。

之后使用：恢复上次桌面 → 正常听歌、打开常用项目 → 想换心情时一键切换收藏 → 偶尔微调并另存 → 自愿分享搭配。

用户不需要每天打开设置页。常驻工具的价值可以是安静地工作，不能把设置页访问次数、进程启动次数当作成功。

## 优先级和最小可交付范围

### P0：先守住信任，作为发布门槛

聚焦已经出现过的问题：拖入/拖出、排序与选中一致、打开遵守系统行为、失焦与输入正常、弹框不闪、失效路径可恢复、退出后桌面项目正确恢复。

验收：混合文件/目录/快捷方式/照片/便签完成挂载和恢复；重启、显示器变化之后顺序不变；无法保存时保留原状态并明确提示；关键回归用例通过。真实休眠、多屏场景需要单独现场验证，不能用模拟结果冒充。

性能先记录同一台电脑、相同分辨率和配置下的基线：空闲、播放音乐、隐藏桌面、全屏应用四种情况。新增内容不得明显恶化输入延迟或空闲负载。建议以同机中位值回归超过 10% 为调查线，这只是团队门槛，不是通用硬件承诺。

### P1：三套完整桌面方案，首先开发

建议成品只有三套，每套明确用途：

| 方案 | 展示重点 | 使用场景 |
| --- | --- | --- |
| 暖砂日常 | 低强度灯效、小音乐卡片、清爽的拾光绳 | 工作间隙听歌、常用项目随手开 |
| 暮蓝听歌 | 稍明显的音乐响应、可读歌词、统一冷色 | 专门听歌、欣赏歌曲 |
| 清浅专注 | 减少运动和装饰、保留轻量音乐信息 | 写作、学习、长时间使用 |

复用现在的“场景收藏”入口，在其中加入精选成品和最近使用；托盘里只给少量收藏的快捷入口。首次提示可跳过，用过后不反复弹出。不要新增一整页日常任务或运营首页。

操作只保留「预览」「应用」「另存为我的方案」；应用后可撤销回前一套。高级参数留在原模块。先保证三套作品的浅/深色、宽屏和常见缩放都好看，不先凑几十套模板。

**数据边界必须明确：**

- 方案保存灯效、歌词展示、音乐卡片展示和配色；拾光绳外观/位置在本次实现中保持独立。
- 切换方案不增删挂载项目、不重排用户项目、不触发桌面隐藏/恢复。挂载关系属于独立的用户数据。
- 首版不随方案更换系统壁纸；在当前壁纸上预览，并复用已有取色能力。
- 不覆盖音源选择、启动项、主题跟随系统等全局偏好。
- 旧场景继续可读；新格式版本化。只包含样式的旧收藏不能清空新模块设置。

技术上需要一个统一的“应用桌面方案”操作：验证所有参数后再写入；多份配置写入失败要回滚，避免歌词已换、灯效没换、拾光绳又变了的半完成状态。不要靠多个独立组件依次调用保存来假装原子切换。

验收：不熟悉软件的测试者能在 2 分钟内得到愿意留下的桌面；连续切换和撤销后原挂载列表完全一致；重新启动保留方案；旧收藏导入仍可用。2 分钟是待检验的设计目标。

### P2：克制的“跟随音乐”，作为第二个实验

只加一个可理解的开关「跟随封面配色」，加一个「固定当前配色」动作。曲目或封面变化时计算一次配色，缓慢过渡；不要每帧取色，也不要让整张桌面随节拍强闪。

第一版仅联动音乐卡片和灯效。歌词优先保证对比度，拾光绳上的程序图标保持原样。封面缺失/纯色时回退方案颜色；暂停时平滑收敛，恢复时继续。离线或歌词获取失败不影响已有场景。

价值假设：同一套桌面随自己常听的歌产生小变化，不需要每天手动换皮肤。沿用现有音乐响应，不叠加一套新的粒子引擎。封面来自已经能合法取得的当前播放数据，不引入音乐账号登录或音源下载服务。

验收：更换十首封面差异明显的歌曲，配色不闪烁、不遮挡文字；快速切歌不被较早的异步结果覆盖；关闭开关能恢复固定配色；减少动态效果模式下不强制动画。

### P3：轻量分享，等前两项有人反复用再做

先升级已有导出为“可预览的搭配文件”，附上明确的版本与效果清单；分享图片先只导出应用自己的场景预览。使用者选择文件、预览、确认应用即可。

分享默认排除本地路径、文件名、私人照片、便签、音源账号信息；不把整份用户配置打包出去。首版也不打包歌曲、歌词或第三方封面资源。导入应用样式，不自动启动程序、挂载陌生文件或运行脚本。

先自己维护少量精选搭配，通过现有发布渠道分发，允许用户继续用文件互传。只有出现稳定的分享与二次修改行为，再讨论在线作品库。作品库还涉及存储、审核、举报、版本兼容和维护，不是加一个上传按钮。

验收：另一台机器能导入并看到合理结果；缺少素材时能预览回退；收件方无法从文件中读到作者的私有挂载信息；无需账号即可完成。

## 排期与控制范围

以下是单名熟悉项目的全栈开发者的粗估，包含功能验证，不含素材版权采购、云服务、跨平台全面适配；不是交付承诺。

| 阶段 | 估算 | 决策 |
| --- | --- | --- |
| P0 关键路径稳定与性能基线 | 3～5 人日；若发现桌面恢复问题则延长 | 先过发布门槛 |
| P1 整套方案保存/预览/撤销 + 三套成品 | 7～10 人日 | 完成后马上找人用，不等待 P2/P3 |
| P2 封面配色联动 | 3～5 人日 | P1 有持续使用迹象再做 |
| P3 可预览的安全分享文件 | 4～6 人日 | 有主动分享需求再投入 |

原建议第一轮只排 P0 + P1。用户现已批准同时实施 P1 + P2，P3 暂不考虑；以上人日是早期估算，不代表实际耗时。保存、撤销和桌面恢复仍是优先验证的路径。

暂缓：连续签到、积分等级、宠物养成、任务墙、全功能启动器、音乐账号聚合登录、自建社区、任意代码插件平台。它们都增加了另一套产品和维护责任，当前没有证据表明能补上主要缺口。

## 如何判断是否有效

先找约 12～20 名目标用户使用两个星期，包含未接触过产品的人。先记录现版体验，再提供 P1 版本；观察顺序和学习效应会影响结果，这只能帮助发现问题，不能据此宣称统计显著的留存增长。

| 要回答的问题 | 观察办法 | 如何作决定 |
| --- | --- | --- |
| 是否更容易得到满意桌面？ | 首次应用时间、需要求助的次数、是否保留这套桌面 | 若仍要解释很多参数，继续改善成品和预览，不加新模块 |
| 是“开过一次”还是反复有用？ | 激活后第 7 天附近（第 6～8 天）是否仍实际使用；两周内使用天数 | 区分主动使用、音乐桌面启用且播放超过 10 分钟、仅开机自启三种情况；不将它们混为一个数 |
| 整套方案值得保留吗？ | 是否保存自己的版本、之后是否再次应用它、是否多次撤销同一模板 | 有收藏却从不复用，就回访原因；先改善切换与适配 |
| 拾光绳是否成为日常工具？ | 跨天打开挂件的次数、取消挂载原因、失败次数 | 频繁恢复桌面可能是不好用，不是互动量高 |
| 是否值得做分享？ | 主动询问分享的用户、实际导出/导入并继续使用的案例 | 没有需求先不建社区，保留现有文件导出即可 |

北极星建议为“每周真正使用桌面方案的天数”，配合挂件跨天使用和故障率一起看。进程常驻时长无法代表价值，纯后台听歌也不能证明用户看见了桌面。前期通过回访问实际场景来校验数据口径。

数据默认本地；愿意参与测试者可主动导出汇总。不采集歌曲内容、文件路径、截图、便签正文或账号。公开版是否加入匿名统计，是后续独立决定。

设置一个止损点：如果连续两轮打磨之后，大家仍只在第一天摆弄一下，第二周普遍关掉，就先问清楚是耗资源、打扰工作、难搭配还是没日常用途。不要用签到奖励掩盖这个问题。

## 同类产品参考与适用边界

下列官方页面于 2026-11-06 查阅。它们说明具体产品能力，不提供留存因果证据；本文关于 SoundSpectra 的优先级是基于现有代码和本次反馈的判断。

- [Wallpaper Engine 官方介绍](https://www.wallpaperengine.io/en)：包含可定制内容、编辑器、社区分享、播放列表与性能控制。可借鉴“成品可直接用、喜欢后再修改”；其大规模内容生态依赖既有创作者和 Steam 分发，不能照搬为当前项目的起点。
- [Rainmeter 官方介绍](https://www.rainmeter.net/)：可定制桌面皮肤、社区作品与工具性质。可借鉴保留个人搭配、修改自己的桌面；不建议当前就开放任意脚本或复制其配置复杂度。
- [Stardock Fences 官方介绍](https://www.stardock.com/products/fences/)：桌面组织、文件夹入口、快速访问等日常用途。可借鉴少步骤访问；SoundSpectra 的拾光绳继续服务自己的音乐桌面定位，无需复制完整生产力套件。
